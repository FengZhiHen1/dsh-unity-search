# 需求

本文唯一拥有 dsh-unity-search 的需求事实：背景与问题、用户与场景、需求条目、非目标、约束与验收语义。技术选型、模块边界与机制细节不归本文。

## 背景与问题

DSH 0.1.2-rc.1 的检索能力现状（已确认事实，证据见本节末）：

- web seam 默认搜索 provider 是 `deepseek-official`，依赖 `DEEPSEEK_API_KEY`；无 key 时原生 `web_search` 不可用。
- free-search 插件提供免 key 网页引擎链与 8 平台定点检索，但无学术源，输出是各引擎结果的归一拼装，无结构化证据契约（哪个源失败、结果是否二手，模型无从判断）。
- modsearch 有证据信封契约（`status/uncertainty/warnings/attempts`），但以 X 语料与 CLI 子进程为主，其 skill 资产未接 DSH skill 机制。
- 学术检索只能经外部 MCP server 桥接，全量工具 schema 常驻成本高（paper-search-mcp 57 工具；zotero-mcp 作者实测 MCP 全量 schema 约 13–23k token/请求）。

问题：检索能力分散、契约不一，默认面与高阶面没有分层。模型要么只有一个裸的搜索框，要么背上一大堆常驻工具；证据可信度信息在传输中丢失。

证据来源：`references/dsh-检索插件调研与统一搜索方案-2026-09-09.md`（五仓库调研，关键论断经独立抽查复核）；DSH 源码检出 `dsh-v0.1.2-rc.1`。

## 用户与关键场景

- 直接消费方：模型 agent（调用原生工具与插件工具、按需加载 skill）。
- 终态用户：DSH 部署者（本仓库维护者本人）——装一个插件获得完整、分层的检索面。
- 受影响面：挂载该插件的 profile 下的全部会话。

关键场景：

1. **默认检索**：模型回答需要联网资料，直接调用原生 `web_search`/`web_fetch`，不需要知道引擎、key、fallback 的存在。
2. **深入检索**：研究型任务中，模型按源族选择学术/平台源，一次调用多源并行，从结构化信封判断证据质量（哪些源成功、是否有跨源佐证）。
3. **资料获取**：给定 URL 读取正文，输出有界、可翻页、可聚焦，不把整篇全文灌进上下文。
4. **长尾扩展**：需要学术长尾源（22 源）或全文 PDF 时，按 skill 指引临时开启官方 MCP 桥——这是配置行为，不依赖本插件新增代码。

## 需求条目

以下 RQ-01 至 RQ-06 的范围已经用户确认（2026-09-09 决策对话：自包含 L0 引擎链；一期源范围 = 网页链 + 学术 3 源 + 平台源 + 有界阅读，见决策记录 DSR-001、DSR-002）。

- **RQ-01 默认检索开箱即用**：安装插件后，原生 `web_search`/`web_fetch` 立即可用。免 key 引擎链兜底，单个引擎失败自动切换；无需任何配置即可获得结果。
- **RQ-02 多源统一检索**：一个工具、一套参数语义，覆盖网页引擎链、学术源（arXiv、OpenAlex、Crossref）、平台源（GitHub、StackOverflow、Hacker News、Wikipedia、npm）。支持一次调用指定多个源并行检索，结果跨源去重合并，并标识哪些条目被多个源同时命中。
- **RQ-03 证据信封**：多源检索的结构化输出恒定携带：总体状态（`ok`/`degraded`/`unavailable`）、逐源成败与错误、不确定清单、告警、逐源尝试记录。证据可信度进结构，不进免责声明。
- **RQ-04 有界资料获取**：给定 URL 读取正文：默认有界输出、分页参数可取后续、可选聚焦词让相关段落优先返回。任何参数组合都不把无界全文灌进上下文。
- **RQ-05 skill 高阶工作流**：插件携带一份 skill：模型经 `skill()` 工具、用户经 `/unity-search` 手势均可加载，加载后获得源选择、查询规划、多源交叉核验、学术检索工作流、长尾 MCP 桥开启方法的成文指引。不加载时模型侧零常驻成本（仅目录条目）。用户或项目可放置同名技能覆盖插件内置版本（定制优先），卸载插件后技能消失。
- **RQ-06 凭据统一**：所有 API key 经 DSH credentials 中心存取（引用名 + 解析链）；插件不建平行配置文件，不要求从进程环境裸读 key，不在插件目录或设置文档中存明文 key。

## 非目标

- X/Twitter 语料：依赖需登录态的第三方 CLI，供应链与合规成本高。
- Zotero 等私有文献库：与公开检索不在同一平面；其写路径（用户核心数据资产）永远不做。
- Sci-Hub 及任何盗版来源。
- 无界全文 PDF 抓取进上下文。
- 一期不做自定义设置卡 UI：设置经 settings 命名空间写 YAML 或原生设置文档即可完成。
- 不吞并任何上游仓库代码：契约设计与端点知识可参考，代码不搬。

## 约束

- **C-01 常驻工具预算**：插件新增的模型可见常驻工具 ≤3 个。依据：token 税反面定价实证（57 工具、13–23k token/请求）；用户要求"默认模式模型无需过多思考"。违反即不合格。
- **C-02 发布前置门禁**：发布 npm 或挂载 web profile 前必须过 test 实测门禁（仓库红线，见根 `AGENTS.md`）。违反即不合格。
- **C-03 部署基线**：DSH 0.1.2-rc.1（部署运行时与源码检出同代，`dshl env` 2026-09-09 当日事实）。跨代升级时需重新核对 seam 与工具 API。

## 验收

验收条件均为可观察结果；括号内为追溯的需求 ID。凡涉及"失败可见"的条目必须按反向验证执行：故意制造一次失败，证明信号真的会响——放松断言、跳过失败注入、伪造通过证据均视为验收不通过。

- **AC-01**（RQ-01）：test profile 直挂启动后，原生 `web_search` 经免 key 引擎返回正常结果；在设置中禁用当前首选引擎后再查，自动 fallback 到下一引擎仍返回结果。
- **AC-02**（RQ-02）：`search_sources` 指定学术三源查真实关键词，返回信封中 ≥2 源成功、`items` 按 DOI/arXiv 标识去重、被多源命中的条目标注 `alsoIn`。
- **AC-03**（RQ-03）：故意配置一个不可达源（如指向无效地址的 SearXNG 实例）并查询，信封 `status` 为 `degraded`、`sources.failed` 含该源与错误原因、其余源结果正常返回。
- **AC-04**（RQ-04）：`read_source` 读取长文 URL，输出长度 ≤ `limit` 且 `truncated: true`，增大 `offset` 可取后续内容；传 `focus` 时相关段落排在内容前部。
- **AC-05**（RQ-05）：会话的 `<available_skills>` 目录含本 skill；`skill()` 工具与 `/unity-search` 手势均能加载；加载后模型能按指引完成一次"学术检索 → 交叉核验 → 有界阅读"流程（人工冒烟判定）。覆盖语义：项目 `.dsh/skills` 放同名技能后项目版生效；卸载插件后技能从目录消失。
- **AC-06**（RQ-06）：key 引擎（如 Tavily）在 credentials 中心录入引用名后可用；`settings.yaml` 与插件目录全文检索无明文 key。
- **AC-07**（C-02）：`dsh --profile test` 启动成功且无 `N entries did not activate`；插件测试套件全绿；core/adapter 分层门禁全绿。
