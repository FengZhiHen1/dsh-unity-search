# 技术栈设计

本文唯一拥有 dsh-unity-search 的技术选型、版本基线、兼容与部署约束及选型理由。模块边界与目录组织归《项目结构设计》；机制细节归 `technical-details/` 各篇。本文约束追溯需求文档的 C-01～C-03。

## 语言与运行时

- **纯 ESM JavaScript**（`"type": "module"`），**无构建步骤**，Node `^22.19.0 || >=24`。
- 理由：① 本仓库既有自研插件（dsh-skill-manager、dsh-guardrails）同形态，模式稳定；② host 半侧零构建使 `github:` git 依赖直挂天然可行——modsearch 的教训是「无 `prepare` 且 `dist/` 不进 git」导致 git 通道拿到半成品，纯源码分发从根上消除该问题；③ JSDoc 承载类型标注，满足可读性即可，信封等运行时契约以 JSON 示例与测试断言为准。
- 重访条件：引入 client 半侧（如设置卡 UI）时按 dsh-skill-manager 先例加 esbuild 单文件构建；届时 host 半侧仍保持无构建。

## 依赖策略

运行时第三方依赖为零。HTML 解析用定向字符串/正则锚点（抓取类引擎天然脆弱，解析与源适配器同址，坏了改一处）；正文抽取一期为自研启发式。

| 包 | 声明位置 | 理由 |
| --- | --- | --- |
| `@deepseek-ai/dsh-tools` | peerDependencies + devDependencies | `defineTool`；携带 Service Definition（module-local `Symbol()` 服务键），双物理副本致命，必须 peer |
| `@deepseek-ai/dsh-settings` | peerDependencies + devDependencies | `installSection`；同上 |
| `@deepseek-ai/dsh-skill` | peerDependencies | skill 注册表 Service Definition；仅声明不 import（`ctx.skills` 经 ctx 注入），按官方携带技能插件范例统一 peer（省 devDependencies） |
| `@deepseek-ai/cordis` | peerDependencies | 同上：官方范例一致声明；不 import 运行时值，省 devDependencies |
| `@deepseek-ai/schemastery` | dependencies | 插件 `Config` schema；跨边界身份是 `Symbol.for`，双副本无害 |

- 不把 `@deepseek-ai/dsh-skill-filesystem` / `@deepseek-ai/dsh-tool-skill` 写进任何依赖：技能的发现与目录是 preset 的所有权，携带技能的插件不该挂它们（反模式，知识库 `agent/24` §9）。
- `files` 必须包含 `skills/`（否则包里没有技能）、`src/` 与 `cordis.patch.yml`。

- 分类判据来源：本仓库知识库 active 版包发布要点（在目标包 lib 搜 module-local `key = Symbol(`，命中即 peer）。
- 重访条件：① 正文抽取质量实测不达标时引入 `@mozilla/readability` + DOM 实现（进 dependencies，README 与决策记录同步）；② 新增携带 Service Definition 的 import 时按同一判据归类。

## DSH 基线与兼容声明

- 开发与部署基线：DSH **0.1.2-rc.1**（部署运行时与源码检出同代，2026-09-09 `dshl env` 当日事实；追溯 C-03）。
- 部署校验一律用实例版本二进制，不用源码检出 CLI。
- `package.json` 声明 `dsh.compatibility.dshReleases`，参考 free-search 的逐版标注做法，供 STORE 复检出数。

## 部署通道

- 一期：`github:` git 依赖，经本仓库 submodule（remote 指向 `FengZhiHen1/dsh-unity-search`）部署；web profile 安装走 `dsh plugin --profile web add github:FengZhiHen1/dsh-unity-search[#ref]`。
- npm 发布：二期评估，登记于 TODO.md。
- 发布或挂载 web 前必须过 test 实测门禁（追溯 C-02）。
- test profile 实测场不涉及真实生产目录写操作；本插件为只读检索型（不写配置所指目录），允许复用真实网络做冒烟，提交说明标注"只读"。

## 测试

- 测试运行器：Node 内置 `node:test`，不引入测试框架。
- core 层单测在裸 node 下运行，不 boot DSH；网络面一律以注入的假 `fetch` 替身覆盖，不做活体网络单测。
- adapter 层接线以 test profile 实测覆盖（启动、`N entries did not activate` 为空、功能冒烟）；官方 boot 级 testkit 组合测试列为二期增强，登记于 TODO.md。

## 安全约束

- **SSRF 防护**：`read_source` 抓取用户给定 URL，仅允许 `http:`/`https:`，DNS 解析后拒绝私网、环回、链路本地地址段，重定向逐跳重新校验；默认不提供关闭开关的便捷路径（设置项 `allowPrivate` 默认 `false`，仅显式配置生效）。
- **UA 诚实**：所有出站请求使用明示产品身份的 User-Agent，不伪装浏览器（对齐官方 `dsh-web-fetch-http` 的原则）。
- **礼貌池**：OpenAlex/Crossref 请求携带设置的 `contact`（mailto）以进入礼貌池；arXiv 遵守其约 3 秒间隔要求（核心层按源限速）。
- **凭据**：API key 只存 DSH credentials 中心，设置文档只存引用名（追溯 RQ-06）。

## 可观测性

- 引擎链与多源调用的失败一律进证据信封（RQ-03），不以静默空结果告终。
- adapter 层用 `ctx.logger('unity-search')` 记录引擎切换、冷却、源失败，级别为 `warn`/`debug`，不向会话注入内容。
