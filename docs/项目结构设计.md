# 项目结构设计

本文唯一拥有 dsh-unity-search 的模块边界、目录组织、依赖方向、命名与全局约定。技术选型归《技术栈设计》；各机制的实现细节归 `technical-details/` 对应篇目。

## 目录组织

```text

├── package.json             # dsh.bundle.patch 声明；peer/deps 分类见《技术栈设计》
├── cordis.patch.yml         # 插件行 insert + web 行双键重述（机制归「L0-Seam接入」）
├── README.md                # 插件使用说明（面向部署者）
├── docs/                    # 设计文档体系（本文档树）

│   │   ├── registry.js      # 源适配器注册表（按 id 与 family 索引）

├── build-client.mjs         # esbuild 构建脚本（复刻 skill-manager 输出格式）
├── skills/                  # 包内静态技能（A 类）：一个技能一个目录，扁平不嵌套
```

## 依赖方向

- 单向依赖：`adapter → core`。**core 禁止 import `@deepseek-ai/*`（含 cordis），禁止相对路径反引 adapter**；core 的一切外部环境（fetch、凭据取值、时钟、配置）经参数注入。
- 门禁：仓库根 `node tools/plugin-layering-check.mjs plugins/dsh-unity-search` 必须全绿（本仓库硬性约定）。
- core 内部：`engines/`、`academic/`、`platforms/`、`read/` 只依赖 `http.js` 与同族工具模块；`chain.js`、`fanout.js` 只依赖 `registry.js` 与 `envelope.js`；禁止适配器之间互相 import。

## 命名约定

| 对象 | 取值 | 说明 |
| --- | --- | --- |
| 包名 | `dsh-unity-search` | 不带 scope（本仓库自研插件惯例） |
| loader 行 id | `unity-search` | `cordis.patch.yml` 内唯一 |
| 插件 `name` 导出 | `unity-search` | kebab-case |
| settings 命名空间 | `unity-search` | 与用户设置文档段配对 |
| seam provider id | `unity-search` | search provider；fetch 不自建，pin 内建 `http` |
| 工具名 | `search_sources`、`read_source` | 与原生 `web_search`/`web_fetch` 明确区分 |
| skill 名 | `unity-search` | == 目录名（官方硬性）；自带插件域前缀——rank 600 同层撞名时先注册的 provider 胜、后者仅 warn，前缀使归属可判断 |
| skill provider 名 | `unity-search-bundled` | 层内唯一；`runtime` 为注册表保留名，禁止占用 |
| 设置节 id / label | `unity-search` / `统一搜索` | `settings.section` 注册（list 条目，`order: 17`） |
| RPC channel | `/unity-search` | Client↔Host 自定义通道（`state`/`test` 端点） |
| 源适配器 id | 见「源适配器清单与端点契约」 | 稳定字符串，进入信封与 settings 键 |

`skills/` 目录归包内静态技能（A 类：技能跟插件版本走、用户不改；判定与结构规范见知识库 `agent/24`），`files` 必须包含它；`src/adapter/skill.js` 只做 provider 接线与 `resourceBase` 路径计算（`new URL('../../skills/unity-search/', import.meta.url)`，构建后相对层级复验），不承载技能内容。

## 全局约定

- **状态载体唯一**：引擎健康/冷却状态保存在 adapter 层 fiber 作用域内的实例对象上（注册进 `ctx.effect` 清理），禁止模块级可变单例。
- **错误语义**：core 内失败一律返回结构化结果（信封/`sources.failed`），不向调用方抛业务异常；仅编程错误（违反接口契约）允许抛出。adapter 层工具 `execute` 遵守「只返回规范 JSON 值」约定。
- **日志**：统一经 `ctx.logger('unity-search')`，core 不打日志（经注入的事件回调上报，adapter 落日志）。
- **测试组织**：`test/` 文件名与 `src/core/` 被测文件同名；adapter 接线不进裸 node 单测。
