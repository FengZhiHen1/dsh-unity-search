# DSR-002 一期源范围

> 决定：一期 = 网页引擎链 + 学术 3 源（arXiv/OpenAlex/Crossref）+ 平台 5 源 + 有界阅读；引文图谱/BibTeX 导出与学术二期源（Semantic Scholar/PubMed/EuropePMC）延期。
> 理由：覆盖"统一多源"的完整故事且验证面可控；引文功能依赖学术源先稳定。
> 被否决项：仅网页链 + 学术 3 源（故事不完整）；全量一次到位（验证面过大）。

## 上下文

RQ-02 要求多源统一检索。候选源族：网页引擎（L0 自包含自带）、学术源、平台源、有界阅读；差异化候选：引文图谱（OpenAlex 引文边）与 BibTeX 导出（五仓库模型面全缺，Crossref 原生支持 CSL/BibTeX 端点）。

## 方向与评价

| 方向 | 何时成立 | 代价与风险 |
| --- | --- | --- |
| 网页链 + 学术 3 源 | 最小差异化、最快过门禁 | 平台源缺席，"统一多源"故事不完整；read_source 缺席则"获取资料"半空 |
| 网页链 + 学术 3 源 + 平台 5 源 + 有界阅读 | 完整覆盖 RQ-02/RQ-04；平台源全是稳定 JSON API，适配器成本低 | 适配器数量 16 个，测试面扩大 |
| 全量一次到位 | 用户不介意工作量 | `get_bibliography` 依赖学术源先稳定；一期验收面过宽，门禁周期拉长 |

评价维度：需求覆盖、验证成本、依赖顺序、二期跟进成本。

## 决定与理由

选中间方案。平台 5 源（GitHub/StackOverflow/HN/Wikipedia/npm）全是 keyless 稳定 JSON API，边际成本低而"统一"收益完整；有界阅读是 RQ-04 的唯一载体，不能延期。引文/BibTeX 与学术二期源延期：端点成本低但依赖学术源实测稳定，且工具面预算（C-01 ≤3）的第 3 个槽位为其保留。

## 重访条件

- 学术三源在 test 实测中表现不稳定（如 Crossref 限速频繁触发）时，二期源的优先级重排。
- 平台源中任一 API 政策收紧（如 GitHub 匿名配额下调）时，该源降级为可选 key 源并重评清单。
