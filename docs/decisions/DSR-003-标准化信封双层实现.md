# DSR-003 标准化信封的双层实现

> 决定：证据信封在插件自有的 `search_sources` 工具完整暴露；L0 seam provider 只做投影（`WebSearchResult`），降级注记走 `content` 字段。
> 理由：seam 结果形状是 DSH 固定的封闭契约，信封无法穿过；分层恰好匹配"默认零思考、高阶全信息"的产品意图。
> 被否决项：放弃信封、各层各自返回裸结果（证据面丢失）；改 seam 契约（上游边界，不可行）。

## 上下文

RQ-03 要求证据信封。已确认事实：web seam 的 `WebSearchResult`/`WebFetchResult` 形状固定（fetch body 的 kind 还是封闭 union，新增 kind 需跨官方包协调）。信封字段（`sources.failed`/`uncertainty`/`attempts`）无处穿过 seam。

## 方向与评价

| 方向 | 何时成立 | 代价与风险 |
| --- | --- | --- |
| 双层实现 | 默认面保持零思考（seam 形状不变），高阶面完整暴露信封 | 同一检索两套用词（投影规则需文档化并测试） |
| 放弃信封 | 只做默认面 | RQ-03 不成立；证据可信度在结构里丢失，回到 free-search 现状 |
| 改 seam 契约 | 信封直达原生工具 | 需改上游 `dsh-web` 封闭契约，超出本插件边界 |

## 决定与理由

选双层实现。seam 投影不是信息丢弃的妥协，而是分层的产品化：默认模式模型不需要证据细节（RQ-01"无需过多思考"），高阶模式经 `search_sources` 获得完整信封（RQ-03）。投影规则集中在 `envelope.js` 一处，两套用词的漂移风险由单测钉住。

## 直接后果

- 波及文档：technical-details/检索核心与信封契约.md（信封 schema 与投影）、L0-Seam接入.md（投影规则）、工具面与有界阅读.md（信封的工具暴露）。
- 投影规则：`degraded` 时 `content` 填降级注记；`unavailable` 抛 `WebError`；`ok` 时无注记。

## 重访条件

- DSH 上游若开放 seam 结果扩展字段，重评信封下钻到默认面的方式。
- 实测发现模型在默认模式下频繁需要证据细节时，重评 `content` 注记的填充策略。
