# DSR-005 设置界面独立标签页

> 决定：UI 面为设置面板左导航的独立设置节（`settings.section`，label「统一搜索」），职责 = 配置 + 状态 + 诊断；推翻此前"一期不做自定义设置卡 UI"的非目标。
> 理由：用户明确指令（2026-09-09）；搜索引擎的最大痛点——哪个引擎坏了、为什么、key 配没配——需要可见面；rc.1 官方 `credentials` Remote 使凭据录入零自建设施。
> 被否决项：一期无 UI（旧非目标）；`settings.plugin.item` 配置卡（形态太小，承载不了状态与诊断）；纯配置面（无 RPC，痛点不可见）。

## 上下文

初版设计把自定义设置 UI 列为二期延期项（原考虑：设置经 YAML/原生文档可配，UI 边际收益低）。用户随后明确调整："UI 面为设置界面中的独立标签页"。此为对旧决定的显式推翻，受影响文档按回退流程逐项更新（见「直接后果」）。

机制事实（知识库 `client/15`、`client/17`，DSH 源码检出复核）：

- 独立设置节 = 注册 `settings.section`（list/root），先例 = Agent 预设、技能（本仓库 skill-manager，含 Client 入口/RPC 通道/构建的全部同构范式）。
- `ctx.remote.credentials`（`describe`/`set`/`unset`，秘密单向过线）使凭据录入不再需要 free-search 当年自搭的 webServer 桥。
- 自定义 RPC channel 继承 loopback/认证围栏，且有 curl 无浏览器验证通道（知识库 `client/17` §7 实证）。

## 方向与评价

| 方向 | 何时成立 | 代价与风险 |
| --- | --- | --- |
| 独立设置节（配置+状态+诊断） | 痛点（引擎健康、key 状态、实跑验证）需要可见面；用户指令 | 引入 client 半侧（esbuild 构建、纯净度门禁、页面维护面）；Host 增 RPC 通道 |
| `settings.plugin.item` 配置卡 | 只要表单配置 | 卡片形态承载不了状态区与诊断区；与"独立标签页"指令不符 |
| 纯配置面（无 RPC） | 实现最省 | 引擎坏没坏、为什么不可用仍不可见——搜索引擎最大的可观测性缺口保留 |

评价维度：需求满足度（RQ-07）、可观测性收益、实施与维护成本。用户已再次声明不介意工作量。

## 决定与理由

选独立设置节，职责 = 配置 + 状态 + 诊断。导航图标接受宿主默认（MutationObserver 改 DOM 是脆弱补丁，一期不做；宿主 DOM 结构变化即失效，维护成本超过收益）。页面不注册 `settings.plugin.item`，避免双入口。

## 重访条件

- 宿主开放导航图标注册或 section 图标机制变化时，重评默认图标策略。
- `settings.section` 契约或纯净度门禁跨代变化时，按新基线重核（C-03）。
- 诊断区实测使用频率极低时，重评是否裁撤 RPC `test` 端点（页面退回配置+状态）。
