# DSR-001 自包含 L0 引擎链

> 决定：插件自带网页引擎链并注册 seam search provider，web profile 后续替换 free-search。
> 理由：统一检索面必须自包含，开箱即用不能依赖另一个插件；效果可控性要求自有信封与链语义。
> 被否决项：与 free-search 共存分工（free-search 续占 L0，本插件只做高阶层）。

## 上下文

当前 web profile 的 L0 由 free-search 承担（pin `searchProvider: ddg` 内含全引擎链 + `fetchProvider: http`），日常在用。本插件的 RQ-01 要求"默认检索开箱即用"。

## 方向与评价

| 方向 | 何时成立 | 代价与风险 |
| --- | --- | --- |
| 自包含引擎链 | 统一检索面作为一个插件交付；信封/冷却/链语义要自有 | 抓取类引擎脆弱面转为自维护；与 free-search 功能重叠，替换前存在 seam pin 仲裁窗口 |
| 共存分工 | 只想要学术/高阶层，不愿背引擎维护 | 插件不自包含；"统一"名不副实；两插件 pin 同一 web 行，层序仲裁长期脆弱 |

评价维度：需求满足度（RQ-01/RQ-03）、概念完整性、维护成本、部署风险。自包含在维护成本维度明确劣于共存，但用户已声明"不介意工作量，更愿意标准化接口和更好的效果"（2026-09-09 对话），该维度的权重被用户显式调低。

## 决定与理由

选自包含引擎链。统一搜索引擎的默认面与高阶面必须同属一个插件，否则"开箱即用"以另一个插件的在场为前提，RQ-01 不成立；证据信封与链语义（冷却、兜底）是"更好效果"的载体，必须自有。
