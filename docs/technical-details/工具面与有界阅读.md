# 工具面与有界阅读

本文唯一拥有：`search_sources`/`read_source` 两个工具的参数、输出与执行语义，以及有界阅读的正文抽取、分页、聚焦与目标校验机制。信封与去重规则归「检索核心与信封契约」；seam 投影归「L0-Seam 接入」。

## 工具面总览（追溯 C-01）

常驻工具恰为 2 个（预算 ≤3，余量留给二期 `get_bibliography`）。与原生工具的分工写进工具描述与 skill：默认网页检索走 `web_search`；需要学术/平台源、多源并行或证据信封时用 `search_sources`；`web_fetch` 是原始取回，`read_source` 是聚焦阅读。

## search_sources

```js
defineTool({
  name: 'search_sources',
  parameters: {
    query:    { type: 'string', required: true, description: '检索词' },
    sources:  { type: 'array', items: { type: 'string', enum: [...] },
                description: '源 id 列表；缺省 ["web"]（网页引擎链）' },
    maxResults: { type: 'number', description: '归并后条目上限，默认 10' },
    timeRange:  { type: 'string', description: 'day|week|month|year 或相对时长如 3d；不支持的源忽略并记 warning' },
  },
  output: { schema: { type: 'json' } /* 信封 */ },
})
```

执行语义：

1. `sources` 缺省 `['web']`；`web` 走引擎链，其余 id 查注册表，未知 id 直接进 `sources.failed`（`code: 'unknown_source'`）并记 `warnings`。
2. 单源退化为链式调用，多源走 fanout；产出恒为完整信封。
3. `output.render` 渲染摘要行（状态、各源成败、前 N 条标题），完整信封即规范值本身——模型读结构不读散文。
- UI 卡片：完成态用 `web` 卡（`kind: search`）呈现；`presentationMeta` 从信封派生可回放 JSON。

## read_source

```js
defineTool({
  name: 'read_source',
  parameters: {
    url:    { type: 'string', required: true },
    focus:  { type: 'string', description: '聚焦问题或关键词，相关段落优先' },
    offset: { type: 'number', description: '字符偏移，默认 0' },
    limit:  { type: 'number', description: '本次返回字符上限，默认 8000，硬上限 20000' },
  },
  output: { schema: { type: 'json' } },
})
```

输出形状：

```json
{
  "url": "最终 URL", "statusCode": 200, "contentKind": "text",
  "title": "抽取到的标题或 null",
  "content": "正文片段", "offset": 0, "limit": 8000,
  "totalChars": 42310, "truncated": true,
  "uncertainty": ["正文抽取置信度低，可能是列表页"],
  "warnings": [],
  "artifactPath": "E:/…/readings/20260909-173000-example-com-a1b2c3d4.txt",
  "artifactKind": "text",
  "artifactBytes": 42310
}
```

`persist: false` 或取回失败时三个 artifact 字段为 `null`（结构恒定完整，不缺省）。

### 有界阅读机制（追溯 RQ-04）

1. **目标校验（SSRF）**：仅 `http:`/`https:`；DNS 解析后逐跳校验（含重定向），拒绝私网/环回/链路本地段；`allowPrivate: true` 时跳过（默认 `false`，见「设置凭据与Skill」）。非 2xx 响应是结果不是异常（`statusCode` 进输出，`content` 为空）。
2. **抽取**：HTML → 去 `script/style/noscript` → 优先 `<article>`/`<main>`，否则按段落文本密度选最大容器 → 去 boilerplate（导航/页脚/侧栏启发式）→ 纯文本（保留段落边界）。`text/*` 与非 HTML 响应直接取原文。抽取置信度低（正文过短/链接密度过高）时记 `uncertainty`。
3. **分页**：`offset`/`limit` 在抽取后的纯文本上切片，`truncated = offset + content.length < totalChars`；`limit` 超过 20000 按 20000 计并记 `warnings`。
4. **聚焦**：传 `focus` 时按关键词重叠对段落打分，高分段落前置（不改变总长度与分页语义——聚焦重排发生在切片前，`offset` 仍相对重排后文本）。`focus` 无命中时不重排并记 `warnings`。
5. **全量落盘（追溯 RQ-04，DSR-006）**：当次取回的全量内容写入落盘目录并在结果返回 `artifactPath`/`artifactKind`/`artifactBytes`——每次调用只存一份：抽取成功 = **全量**抽取文本（不受 `limit` 约束）；抽取失败 = 原始 body（`artifactKind: 'raw'` + `warnings` 明示）。落盘是上下文外的第二通道：Agent 发现返回内容不足或疑似抽取失真时，自行 read/grep 落盘副本，无需重抓（避开限速与反爬）。
6. **不变量**：任何参数组合下 `content.length <= limit`；全文永不一次性返回**进上下文**（paper-search-mcp 整篇灌上下文的教训）——落盘文件在上下文之外，不动摇本不变量。

### 落盘管理

- 目录：默认 `$DSH_HOME` 下插件数据目录（不污染用户工作区）；`readSource.dir` 可覆盖。文件名 `{YYYYMMDD-HHmmss}-{host}-{hash8}.txt|html`。插件向该目录写文件 ⇒ test profile 必须把 `dir` 指向 fixture 目录（test 隔离红线，登记于 TODO.md）。
- 保留：目录总量超 `readSource.maxTotalMB`（默认 256）按最旧先删（LRU）；`persist: false` 整体关闭。
- 取回本身失败（网络错误/SSRF 拒绝/响应超限）→ 无 artifact（没有内容可存）；非 2xx 无 body 同此。
- 安全：落盘暴露面与会话日志同级（会话日志本已持久化工具结果全文）；`allowPrivate: false`（默认）下私网内容根本到不了落盘。

## 执行约定

- 两工具均遵守 `exec.signal`（取消透传到 core `fetch`）；只返回规范 JSON 值；基础设施故障才抛异常（isError 路径）。
- `timeoutMs` 声明 60s（工具注册表不强制执行；core 内 `chain.timeoutMs` 与阅读超时自行收口）。
- 卡片方法为纯函数：不做 I/O、不读会话状态。

## 验证方式

- 单测：抽取器对 HTML 样本（正文页/列表页/纯文本）的输出、分页边界、聚焦重排、SSRF 目标分类（私网/环回/公网域名经注入的假 DNS 解析）；落盘文件形态（成功 `text` / 抽取失败 `raw`）、LRU 驱逐、`persist: false` 不产 artifact。
- 冒烟（test profile）：长文 URL 分页遍历 + artifact 存在性与 raw 回退（追溯 AC-04/AC-09）；`search_sources` 学术源 fanout（≥2 源成功，追溯 AC-02）。
