# 检索核心与信封契约

本文唯一拥有：源适配器接口、证据信封 schema、引擎链兜底语义、多源 fanout 归并、跨源去重规则。这些机制的消费方（seam 投影、工具、skill）归各自篇目，本文只定义核心契约。

## 目标与边界

core 层把"从多个异构源检索并获取资料"归一成两个动作：**检索**（`search`）与**读取**（`read`，读取的输入输出归「工具面与有界阅读」）。所有检索路径产出同一个证据信封——这是本插件的标准化接口，追溯 RQ-02、RQ-03。

## 源适配器接口

每个源一个适配器对象，纯数据 + 函数，无类、无状态：

```js
{
  id: 'arxiv',                    // 稳定 id，进信封与 settings 键
  family: 'academic',             // 'web' | 'academic' | 'platform'
  // 本地廉价可用性判断：不发起网络请求，只看注入的配置与凭据
  available(runtime): boolean,
  // 执行一次检索；失败返回 { status: 'error', error }，不向调用方抛业务异常
  search(request, runtime): Promise<SourceOutcome>,
}
```

`request`：`{ query: string, maxResults?: number, timeRange?: string }`。`timeRange` 取值 `day|week|month|year` 或相对时长（如 `3d`），不支持的源忽略该参数并在 `warnings` 记一条。

`runtime`（adapter 层组装注入，core 不感知 DSH）：`{ fetch, signal, resolveCredential(ref), contact, logger }`。

`SourceOutcome`：

```json
{
  "status": "ok | error",
  "items": [
    {
      "title": "...", "url": "...", "snippet": "...",
      "publishedAt": "ISO-8601 或缺省",
      "sourceIds": { "doi": "...", "arxiv": "..." },
      "extra": {}
    }
  ],
  "answer": "源自带答案/摘要（可选，如 Perplexity）",
  "error": { "code": "rate_limited", "message": "HTTP 429" },
  "latencyMs": 123
}
```

- `sourceIds` 承载源内稳定标识（学术源的 DOI/arXiv id/PMID、平台的仓库全名/问题 id），是去重的第一依据；`extra` 放源特有字段（学术：`authors`/`venue`/`citationCount`；平台：`stars`/`answerCount`），不进通用排序逻辑。
- `error.code` 用开放短字符串（`rate_limited`/`timeout`/`http_4xx`/`http_5xx`/`parse_failed`/`network`），消费方必须容忍新增取值。

## 证据信封

所有检索路径（引擎链、多源 fanout）的归一输出：

```json
{
  "status": "ok | degraded | unavailable",
  "query": "原始查询",
  "sources": {
    "queried": ["web:bing", "arxiv"],
    "succeeded": ["arxiv"],
    "failed": [{ "source": "web:bing", "code": "http_5xx", "message": "..." }]
  },
  "items": ["归并去重后的条目，见下"],
  "duplicatesRemoved": 2,
  "answer": "可选的源自带答案（单源且有 answer 时透传）",
  "uncertainty": ["与结果平级的不确定清单"],
  "warnings": ["非致命问题，如 timeRange 被某源忽略"],
  "attempts": [{ "source": "arxiv", "outcome": "ok", "latencyMs": 123 }]
}
```

- **status 归并**：全部成功 → `ok`；有成功但也有失败/跳过 → `degraded`；全部失败 → `unavailable`。`unavailable` 时 `items` 为空数组，信封仍完整返回（工具层不抛异常）。
- **items 条目** = `SourceOutcome.items` 元素 + `alsoIn: [源 id]`（跨源命中归并，见去重节）+ `source: 首选来源 id`。
- **uncertainty 语义**：与结果平级的不确定声明，例：`"arxiv 结果仅含摘要级元数据"`、`"该主题时效性强，部分源未按时间窗过滤"`。它是产品契约而非装饰——模型据此决定是否需要交叉核验。
- **逐源失败必须可见**：上游 4xx/5xx/解析失败进 `sources.failed`，绝不静默归零（paper-search-mcp 实测 403 静默成 0 结果的教训）。

## 网页引擎链（chain）

`family: 'web'` 的适配器不单独暴露给 fanout，而是组成一条**健康感知顺序兜底链**，对外视为一个逻辑源 `web`：

1. 顺序：settings 的 `chain.order`（缺省引擎被跳过）。
2. 逐个尝试：第一个返回 `ok` 且 `items` 非空的引擎胜出，其结果作为 `web` 源的 `SourceOutcome`。
3. 失败处理：失败引擎进入冷却（`chain.cooldownSeconds`，默认 300 秒），冷却期内 `available()` 返回 `false`；空结果不算失败（换查询词是模型的事，不换引擎），但记录进 `attempts`。
4. 全部失败：`web` 源整体 `error`，进入信封 `sources.failed`。
5. key 引擎：`resolveCredential(ref)` 取不到值即 `available() === false`，不参与兜底。

链的胜出一律经注入的事件回调上报（adapter 落 `debug` 日志）；冷却状态存活于 fiber 作用域实例（约定见《项目结构设计》「全局约定」），不持久化。

## 多源 fanout 与去重

`search_sources` 工具指定多个源时（含 `web` 逻辑源），`fanout.js` 并行调用（`Promise.allSettled` 语义），逐源结果进 `attempts` 后归并：

去重键按优先级取第一个可用：

1. `sourceIds.doi`（小写归一）；
2. `sourceIds.arxiv`；
3. 规范化 URL（去协议 `www.`、去尾斜杠、去 `utm_*` 等追踪参数、小写 host）；
4. 标题小写 + 首个作者/owner（学术与平台条目的兜底）。

命中同一键的多个条目合并为一个：`source` 取 family 优先级高者（`academic` > `platform` > `web`，同族取先返回者），`alsoIn` 记录全部命中源 id，`extra` 字段并集（冲突取首选来源的值）。`duplicatesRemoved` 记合并条数。

**不变量**：信封结构恒定完整（字段不缺省）；`items` 永不重复（同一去重键只出现一次）；`sources.queried` = `succeeded` ∪ `failed`（按源 id 计）。

## 限速与资源界

- 按源最小间隔：`arxiv` 3000ms（其服务条款要求），其余源默认 1000ms，经 `http.js` 的按 host 节流闸实现。
- 单源超时：`chain.timeoutMs`（默认 15000ms），`exec.signal` 取消全程透传。
- 响应大小界：检索类响应 1 MB、阅读类 5 MB（对齐官方 `web-fetch-http` 的 `maxResponseBytes`），超限按 `error.code: 'too_large'` 处理。
- 429/5xx 不重试（失败进信封，链内下一引擎兜底）；网络错误同样不重试。重试策略如有需要属二期增强。

## 验证方式

- 单测（裸 node + 假 `fetch`）：状态归并真值表、去重键优先级与 `alsoIn` 归并、冷却状态机、限速闸、限速/超时/超限失败进信封。
- 反向验证：注入一个恒定失败的源，断言信封 `degraded` 且 `sources.failed` 完整（追溯 AC-03）。
